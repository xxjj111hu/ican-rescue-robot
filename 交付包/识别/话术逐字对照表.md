# 识别话术逐字对照表

> 唯一来源：`sim_ws/src/ican_recognize/ican_recognize/scripts_table.py`
> 依据：《应急救援机器人裁判系统判分细则 V1.0》第 4 章 表 5（陆地障碍物清除任务点识别）

## ⚠️ 关于"细则原文"的说明（重要，必读）

判分细则 PDF 是**多栏排版**，直接复制文本会把版面标签（`陆地障碍物清除任务`、`点识别`）
**混进句子中间**。例如从 PDF 复制出来的实际内容是这样：

```
已识别到坍塌废墟，前方道路被废墟阻
坍塌废墟                        已识别到坍塌废墟
点识别                   断，开始清除障碍，打通救援通道。
```

如果把这种交错文本当作"原文"，会得出"我方实现有差异"的**错误结论**，进而可能把
**本来正确的字符串改错** —— 而话术错一个字就是该点 **0 分**。

下表"细则原文"列是按语义还原后的基准串，并与代码里的 `_FROZEN_SCRIPTS` 一致，
`validate_scripts()` 会强制比对，任何人改动都会让运行自检失败。

## 判分口径（细则第 4 章）

细则原文：裁判系统依据**裁判匹配关键词**判断识别是否正确，**识别话术中须包含对应匹配关键词内容**。

即：严格判据是"包含关键词"。但我们仍按**整句逐字一致**实现 —— 因为《任务说明书》要求
"逐字一致，错一个字该点 0 分"，取更严的口径没有额外代价，只会更安全。

## 实现约定

- 话题：`/referee/detections`，类型 `std_msgs/String`，QoS **RELIABLE**（与裁判侧一致）
- 时机：**进入点位之前**发布；识别不稳定时先重试，不发空消息、不静默跳过
- 自检：节点启动时调用 `validate_scripts()`，校验
  1. 5 类齐全
  2. 每条话术包含对应匹配关键词
  3. 无换行、无首尾空白、以「。」结尾
  4. **无半角逗号**（必须是全角「，」）
  5. **与冻结基准逐字一致**
- 唯一来源：全项目只有 `scripts_table.py` 一处定义，其它模块 import，不复制字符串
