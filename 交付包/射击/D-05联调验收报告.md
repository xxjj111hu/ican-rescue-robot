## 三、实现要点

### 3.1 环形靶（视觉）

标准十环靶纸 `黑边 → 红(6) → 白(7) → 蓝(8) → 黑(9) → 黄心(10)`，
实测靶直径 82 px、每环 8.2 px。

| 目标环 | 允许横向偏差 |
|---|---|
| ≥8 环 | ≤ 24.6 px |
| ≥9 环 | ≤ 16.4 px |
| 10 环 | ≤ 8.2 px |

**关键参数**（都与实测标定过）：

- `roi_y_max_ratio: 0.53` —— 0.55 时蓝环被地面贴图污染，真靶只剩红色检出
- `REQUIRE_INNER_COLOR` —— 必须检出蓝/黄内环，否则判为误检（挡掉纯红假目标）
- `tol_px: 8`、`settle_sec: 0.25`、`aim_gain: 0.004`、`aim_timeout_sec: 20`

### 3.2 旋转靶（几何时序）

从 `land_shoot.world` 挖出的结构（已数值核对，误差 < 1e-5）：

```
leaf_k  →  WheelLeaf(k+1)Texture  →  靶位 k+1
φ_k = 90° − 72°·k      半径 0.09 m，叶片尺寸 0.01×0.05×0.05
```

**关键物理约束**：叶片排在半径 0.09 m 的圆环上、**圆心是空的**，而子弹从 0.26 m
高度水平射出、正好穿过轮心 —— **正对轮心射击一发都打不中**。必须：

1. 等目标叶片转到左右水平位置（竖直偏移 ≤ 25 mm）
2. 车头偏 ±atan(0.09/1.55) ≈ 3.33° 对准该叶片

`side`（左右侧）必须用"沿旋转方向下一个窗口"，不能用"最近窗口"——后者每转 180°
就翻转一次，车头目标在 ±3.3° 之间反复跳，横向偏差永远收敛不了（实测卡在 +107 mm）。

### 3.3 移动靶

单板 0.02×0.18×0.07 + 一张贴图（3 个码画在贴图上，非独立几何），
沿 x 往复 ±0.15 m。按板的 yaw 把码的本地偏移旋转到世界坐标，闭环对准后开火。

靶位编号顺序无法从 world 文件读出，做成参数 `moving_code_order`（默认 `"678"`）。

### 3.4 分点调度（D-05）

```
任务节点 after_arrived(task_N)
  → publish_referee_target(N)
  → ALIGN_YAW：odom 闭环把车头转到航点 yaw（容差 0.4°）
  → AIM_SHOOT：异步调 /ican_shoot/fire_* ，超时 40 s 强制继续（不中断优先）
  → wp_index+1，进入下一点
```

**AIM_SHOOT 期间任务节点不发 `/cmd_vel`** —— 否则会和射击节点的转向命令打架。

## 四、关键坑（都实测踩过，按重要性排序）

### 4.1 ⚠️ DDS 图污染 —— 最隐蔽、最费时

**现象**：`/odom` 在 98 Hz 正常发布、`ros2 topic info` 显示订阅已建立，但节点内
回调**从不执行**；`ros2 topic info -v` 里出现 `_NODE_NAME_UNKNOWN_` 幽灵条目；
`ros2 node list` 还残留已退出进程的名字；甚至反复 launch 后出现
`WARNING: nodes in the graph that share an exact name`。

**根因**：反复 `pkill -9` 强杀 + 立刻重启同名节点，DDS 发现数据库里留下僵尸记录。

**它伪装成了 6 种不同的 bug**：odom 收不到、det 冻结、参数查不到、节点不在图里、
`/cmd_vel` 9 个发布者、环形靶假阳性 —— 让我在错误方向上反复试错。

**规避（必须）**：
```bash
pkill -9 -f <node>
ros2 daemon stop          # ← 关键
bash sim_ws/stop_all.sh   # ← 会清 FastRTPS 共享内存
sleep 5
ros2 daemon start
bash sim_ws/start_all.sh --no-mission
```
**不要**在同一个会话里反复 pkill + 重启同名节点。

### 4.2 服务回调里做长任务会饿死订阅

默认回调组是 `MutuallyExclusiveCallbackGroup`，同组回调严格串行 —— 服务回调一阻塞，
同节点的订阅回调全部停摆。修法：**订阅与客户端放独立回调组、服务放另一个组**，
并把长时间工作放到**普通线程**（`_run_in_thread`）。

**注意：`_io_group` 必须用 `MutuallyExclusiveCallbackGroup`，不要用 `Reentrant`** ——
实测 Reentrant 的 `can_execute()` 恒为 True，会让组内订阅互相饿死。

### 4.3 其他（按时间顺序）

| 坑 | 后果 | 规避 |
|---|---|---|
| 官方示例容差 ±25 px | 只能打 8 环 | 收到 ±8 px |
| 靶心数字"10"干扰取样 | 颜色采样得偏暗假值 | 用区域聚类而非单点采样 |
| ROI 取 0.55 | 蓝环被地面污染，真靶只检出红色 | 收到 0.53 |
| 只看红色能通过 | 画面右侧纯红物体被误检（r=47、dx=+378px） | 要求检出蓝/黄内环 |
| `cv2.imread` 读中文路径 | 静默返回 None | `np.fromfile` + `imdecode` |
| `/gazebo/get_entity_state` 服务 | 程序调用请求发出、响应永不返回（连续 17 次）；`get_model_list` 直接卡死 | 改用 `/gazebo/model_states` **话题** |
| Trigger 服务"先返回后更新" | 无效，response 已发出 | 阻塞式服务 + 线程 |
| `/clock` 停滞时 ROS 定时器不触发 | 节点静默不动作 | 墙钟 + `time.sleep` |
| `/odom`、`model_states` 用 RELIABLE | 收不到（Gazebo 用 BEST_EFFORT） | `qos_profile_sensor_data` |
| 旋转靶对轮心瞄准 | **一发都打不中**（圆心是空的） | 等叶片到水平位 |
| `side` 用"最近窗口" | 车头目标反复跳，横向永不收敛 | 用"沿旋转方向下一个窗口" |
| 竖直条件不满足就不转车头 | 车头永远不转 | 提前转身，不等窗口 |
| `/shooter/shoot` 响应 5.9~19.9 s 不稳定 | 阻塞等会拖死状态机 | 只短探测 2 s |
| Nav2 停车 yaw 偏差达 12° | 0.27 m 宽的环形靶整块出画 | 进点后 `ALIGN_YAW` |
| 任务节点在 AIM_SHOOT 发 `/cmd_vel` | 与射击节点抢话题，车抖动 | 进狙击前停一次即可 |
| `setup.cfg` 带 UTF-8 BOM | colcon 报 `MissingSectionHeaderError` | 写文件不加 BOM |

## 五、能力边界：D-02 的环数无法在练习环境验证

### 5.1 Gazebo 不在贴图上打孔

射击后抓图放大 8 倍，靶纸完好无损 —— 命中判定靠物理碰撞接触，
**相机画面里看不到弹孔**。差分法也被光照/位姿差异淹没（配准残差 MSE=144）。

### 5.2 仿真没有计分话题

`ros2 topic list` 全量检查：只有 `/shooter/shot`（子弹名），
**没有任何 score / hit / referee 话题**。

### 5.3 结论

| 项 | 结论 |
|---|---|
| 瞄准精度 | ✅ `dx=+6.9 px`，每环 8.2 px → **约 0.8 环偏差** |
| 估算环数 | **9.2 环**（按 dx 与环距换算） |
| 实际环数 | ❓ 取决于"相机光轴 = 弹道方向"这一前提，**需裁判系统确认** |

**这是练习环境的能力边界，不是实现缺陷。** 正式比赛由裁判系统给出环数。

## 六、复现步骤

```bash
# ① 编译
cd ~/ican-repo && git fetch win && git merge win/main
cd sim_ws && source /opt/ros/humble/setup.bash
colcon build --packages-select ican_shoot ican_nav_tasks --symlink-install
source install/setup.bash

# ② 干净起环境（关键：不要反复 pkill 重启）
pkill -9 -f shooter_node; pkill -9 -f sequential_mission
ros2 daemon stop; sleep 1
bash ~/ican-repo/sim_ws/stop_all.sh; sleep 5
ros2 daemon start; sleep 1
bash ~/ican-repo/sim_ws/start_all.sh --no-mission
# 等 ✅ /navigate_to_pose 可用

# ③ 起射击节点（一次）
nohup ros2 launch ican_shoot shoot_all.launch.py dry_run:=true > /tmp/f2.log 2>&1 &
sleep 8
ros2 node list | grep shooter     # 必须有 /ring_shooter_node 和 /target_shooter_node

# ④ 起任务节点
nohup ros2 launch ican_nav_tasks nav_tasks.launch.py enable_shooting:=true > /tmp/f2m.log 2>&1 &

# ⑤ 5~8 分钟后查看
grep -E "\[狙击\]|shot:|\[对准\]" /tmp/f2m.log
cat ~/.ros/ican_nav_tasks/mission_result.txt
```

**实弹**：把 `dry_run:=false`。注意细则 §1.3(3)「每个任务点只认第一次命中」，
实弹后需重启仿真才能重置成绩。
