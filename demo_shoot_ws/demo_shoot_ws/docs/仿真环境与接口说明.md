# iCAN 射击练习仿真环境接口说明

## 安装

```bash
sudo apt update
sudo apt-get install --reinstall -y ./packages/ican-shoot-sim-practice_0.1.0_amd64.deb
```

## 启动

```bash
source /opt/ros/humble/setup.bash
source /opt/ican_shoot_sim/setup.bash
ros2 launch ican_shoot_sim sim.launch.py
```

## 随机更换射击地面贴图

射击场有 5 个地面视觉点，位置和尺寸与识别任务一致：0 号点位于 `(1.115218, -1.356470)`，小车无需导航到此处；1～4 号点为实际射击任务点。原点的 `command_center` 仍保持纯色，不是 0 号任务点。贴图候选沿用识别任务的 5 个地面类别：坍塌废墟、滑坡塌方、被困人员、受损车辆和救援营地。每次从每个类别各选择一张候选图片，再随机分配到 0～4 号点，因此五个类别各出现一次。贴图保持 `rotate 90` 规则，目标板方向按识别任务使用 yaw `0` 或 `1.5708`。

首次在当前机器配置共享写权限（只需输入一次密码）：

```bash
source scripts/setup_env.sh
./scripts/randomize_ground_textures.sh --setup-permissions
```

为其他用户配置同样的免密码权限：

```bash
./scripts/randomize_ground_textures.sh --setup-permissions --add-user 用户名
```

用户重新登录，或执行 `newgrp ican_shoot_sim` 后即可直接运行：

```bash
./scripts/randomize_ground_textures.sh
```

可用 `--seed 数字` 复现同一组贴图，`--dry-run` 只显示映射不修改文件。随机结果记录在已安装仿真目录下的 `shooting_texture_assignment.json`。替换后需要重启 Gazebo。

脚本运行日志保存在当前工作空间的 `logs/randomize_ground_textures.log`，权限不足、候选贴图缺失、材质/世界文件异常以及替换失败都会记录。

## 已提供内容

| 内容 | 说明 |
|------|------|
| Gazebo 世界环境 | 比赛练习场地、任务点、指挥中心、挡板和围墙 |
| 小车模型 | 麦轮小车、相机、雷达、里程计和 TF |
| 靶子模型 | 固定靶、旋转靶、两个平移靶 |
| 靶子运动 | 旋转靶持续旋转，平移靶按预设轨迹运动 |

## 参赛者常用接口

| 名称 | 消息类型 | 方向 | 说明 |
|------|----------|------|------|
| `/cmd_vel` | `geometry_msgs/msg/Twist` | 发布 | 控制小车平面运动 |
| `/odom` | `nav_msgs/msg/Odometry` | 订阅 | 小车里程计 |
| `/scan` | `sensor_msgs/msg/LaserScan` | 订阅 | 二维激光雷达 |
| `/camera/image` | `sensor_msgs/msg/Image` | 订阅 | 前向相机图像 |
| `/camera/camera_info` | `sensor_msgs/msg/CameraInfo` | 订阅 | 相机内参 |
| `/tf` | `tf2_msgs/msg/TFMessage` | 订阅 | 动态坐标变换 |
| `/tf_static` | `tf2_msgs/msg/TFMessage` | 订阅 | 静态坐标变换 |
| `/gazebo/model_states` | `gazebo_msgs/msg/ModelStates` | 订阅 | Gazebo 模型状态 |
| `/shooter/shoot` | `std_srvs/srv/Trigger` | 调用 | 发射一发子弹 |
| `/referee/current_target` | `std_msgs/msg/String` | 发布 | 到达点位并准备射击前，通知裁判系统当前射击点位 |

## 射击任务点地面贴图

0～4 号地面点仅在视觉部分使用地面贴图，坐标、尺寸和贴图方向与识别任务一致；0 号点只用于地图显示，不纳入小车导航和裁判点位通知。原点 `command_center` 不使用任务点贴图。所有图片材质均按识别任务规则使用 `rotate 90`；模型 yaw 与材质旋转分别控制位置方向和图片内容方向。

| 任务点 | 材质 | 图片 |
|--------|------|------|
| 0 号（`task_point_0`） | `ShootingGroundTarget0` | 每次随机分配 |
| 1 号 | `ShootingGroundTarget1` | 每次随机分配 |
| 2 号 | `ShootingGroundTarget2` | 每次随机分配 |
| 3 号 | `ShootingGroundTarget3` | 每次随机分配 |
| 4 号 | `ShootingGroundTarget4` | 每次随机分配 |

## `/cmd_vel` 控制说明

`/cmd_vel` 使用 `geometry_msgs/msg/Twist`：

| 字段 | 说明 |
|------|------|
| `linear.x` | 小车前后方向速度 |
| `linear.y` | 小车左右方向速度 |
| `angular.z` | 小车 yaw 角速度 |

示例：

```bash
ros2 topic pub /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.2, y: 0.0, z: 0.0}, angular: {z: 0.0}}" -r 10
```

## 传感器参数

| 传感器 | 参数 |
|--------|------|
| 雷达 `/scan` | 360 点，范围 `-pi` 到 `pi`，量程 `0.10m` 到 `12.0m` |
| 相机 `/camera/image` | 分辨率 `800x800`，频率 `30Hz` |

## 裁判点位通知

到达任务点并准备射击前，需要向 `/referee/current_target` 发布当前射击点位。裁判系统收到该消息后，会把后续射击计入对应点位。

| 点位 | 发布内容 |
|------|----------|
| 1 号任务点 | `shoot_1` |
| 2 号任务点 | `shoot_2` |
| 3 号任务点 | `shoot_3` |
| 4 号任务点 | `shoot_4` |

示例：

```bash
ros2 topic pub --once /referee/current_target std_msgs/msg/String "{data: shoot_1}"
```

## 射击服务

调用 `/shooter/shoot`：

```bash
ros2 service call /shooter/shoot std_srvs/srv/Trigger {}
```

也可以调用兼容接口：

```bash
ros2 service call /shooter/fire std_srvs/srv/Trigger {}
```

服务返回的 `message` 字段为本次生成的子弹模型名。子弹默认从 `shout_link` 前方发射，发射高度为 `0.26m`。

## 坐标系

| 坐标系 | 说明 |
|--------|------|
| `odom` | 里程计坐标系 |
| `base_footprint` | 小车底盘平面坐标系 |
| `base_link` | 小车主体坐标系 |
| `laser_link` | 雷达坐标系 |
| `camera_link` | 相机坐标系 |
